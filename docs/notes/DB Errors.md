- 🐛 📋 Phase 4c — **Effect magnitudes stored in `effects.modifier` instead of `item_effects.value`; bonus type discarded.** Root cause confirmed (2026-07-24) against cached wikitext in `.wiki-cache/`: the wiki's enchantment-template grammar is `{{Effect|magnitude|bonus-type}}` — e.g. `Item:Legendary Large Shield of the Fallen Age` has `{{Incite|59|Insightful}}` and `{{Conditioning|15|Legendary}}`. But `parse_effect_template` (`scripts/src/ddo_data/dat_parser/effects.py`, the `len(params) >= 2` branch) assumes params[0] is a *textual* modifier, so the magnitude ("59") lands in the TEXT `modifier` column and the **actual bonus type ("Insightful"/"Legendary") is thrown away** — data loss that matters once stacking rules consume effects. Single-param templates parse correctly (`{{Incite|120}}` → `value=120`), which is why both shapes coexist for the same effect name; signed/percent single params (`{{Incite|+91}}`, `…|59%}}`) fail `isdigit()` and also land in modifier. Symptoms: numbers ("59", "20") render in the Enchantments type-chip column, and near-duplicate effect rows proliferate (`Incite` has ~40 rows differing only by magnitude). 149 effects rows affected (140 bare-numeric + 9 signed/percent) across 30 effect names, reaching 613 `item_effects` rows. Worst offenders: Diversion (20), Incite (20), Spell Resistance (18), Assassinate (8), DR (8), Armor-Piercing (7+4 as "ArmorPiercing"). Fix direction: teach `parse_effect_template` the `{{Effect|value|bonus-type}}` grammar — numeric-ish first param (int, `+N`, `N%`) → `value`, second param → modifier/bonus-type; keep the Clicky special case; then dedupe the effects table and re-key `item_effects`. Reproduce:
	- `SELECT name, modifier, COUNT(*) FROM effects WHERE modifier GLOB '[0-9]*' GROUP BY name, modifier;`
	- Parser-level: `parse_effect_template('{{Incite|59|Insightful}}')` → `{'effect': 'Incite', 'modifier': '59', 'value': None}` (should be `value=59`, modifier/bonus-type `'Insightful'`)
- 🐛 📋 Phase 4c — **Same name normalized two ways:** `Armor-Piercing` and `ArmorPiercing` coexist as separate effect names (7 and 4 numeric-modifier rows respectively). Effect-name normalization pass needed alongside the dedupe above.
