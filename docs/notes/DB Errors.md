- 🐛 📋 Phase 4c — **Effect magnitudes stored in `effects.modifier` instead of `item_effects.value`.** The scraper parses "Incite 59" as `name='Incite', modifier='59'` — the magnitude lands in the TEXT `modifier` column (meant for variant tags) instead of the INTEGER `value` column. Symptoms: numbers ("59", "20") render in the Enchantments type-chip column, and near-duplicate effect rows proliferate (`Incite` has ~40 rows differing only by magnitude; some keep a `+` sign: `+101`, `+91`). Contrast with correct rows like `Rough Hide` where `item_effects.value=14`. 143 effects rows have purely-numeric modifiers. Worst offenders: Diversion (20), Incite (20), Spell Resistance (18), Assassinate (8), DR (8), Armor-Piercing (7+4 as "ArmorPiercing"). Fix direction: parser routes trailing magnitudes to `item_effects.value`, dedupes the effects table, and re-keys item_effects. Reproduce:
	- `SELECT name, modifier, COUNT(*) FROM effects WHERE modifier GLOB '[0-9]*' GROUP BY name, modifier;`
