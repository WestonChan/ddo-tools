### Unrecognized enchantment templates — the largest data loss found

A corpus-wide census of every template appearing in a cached item's `enhancements` field, compared against what the DB stores. Independently confirmed against Maetrim's DDOBuilderV2 `.item` files (see the cross-check section below).

Both of the first two entries are deferred to **Phase 4m** (decided 2026-07-28) rather than folded into 4c, to keep 4c's review surface at what was approved. They are the highest-value items on 4m's list and the reason 4m should be picked up promptly — **`{{Enhancement bonus}}` blocks Phase 8**.

- 🐛 📋 Phase 4m — **`{{Enhancement bonus|w|N}}` — the core `+N Enhancement Bonus` — is missing from 4,037 items.** 4,055 cached items carry the template (variants: `Enhancement bonus` 3,790, `Enhancement_bonus` 256, `enhancement bonus` 12, `enhancement_bonus` 1); **only 18 produced a bonus row.** The first param is the item kind (`w` weapon / `a` armor), the second the magnitude. **`items.enhancement_bonus` being 100% NULL is the same bug, not a separate one.** Independent confirmation: Maetrim records a `WeaponEnchantment` value on 3,002 of the 6,928 name-mappable items where we record zero, and 3,569 `WeaponEnchantment` + 958 `ArmorEnchantment` buffs across his full set. Noticed by the user on [item 3179](http://localhost:5173/ddo-tools/resources/items/3179) (`Helm of the Warblade`), whose only drop location renders with no pack, patron or level — an empty metadata line under "Drops from". It is not.

### Found while fixing 4c — 2026-07-29

- ⚠ **A near-miss worth remembering: two normalization passes were mutually recursive with disagreeing rules.** `renormalize_bonus_names` rebuilds `bonuses.name` from `stats.name` + `value`; `collapse_value_variants` groups spellings by stripping punctuation — so `Constitution -2` and `Constitution +2` shared a variant key, the penalty was folded onto its positive twin, then rebuilt, forever. **Row counts never moved while 18 negative bonuses flipped sign on every build**, and `build-db` runs `collapse` last, so the wrong sign is what would have shipped. Fixed by treating a sign in front of a digit as meaning rather than punctuation. Lesson for any future change to either pass: it needs a **convergence** test, not a row-count test. Repro (historical): `SELECT id, name, value FROM bonuses WHERE value < 0;` — every name should carry a minus.
- 🐛 📋 Phase 4m — **Crafting-table duplication is a bug, not data.** `crafting_options` holds exactly **4 identical copies of each of 1,119 options** (histogram `{4 copies: 1119}`, no exceptions) and `crafting_recipes` is 4 × 127 — four historical build runs, because neither table has a unique index for `INSERT OR IGNORE` to work against. 4c stopped the growth (the writers now look up existing identities) but deliberately left the copies. The structural fix is a `UNIQUE INDEX` on `crafting_options(system_id, tier, name)`, matching this repo's convention elsewhere — it **cannot be created until the copies are merged**, because their `crafting_option_bonuses` / `crafting_recipe_ingredients` children need merging too. Repro: `SELECT COUNT(*) c FROM crafting_options GROUP BY system_id, tier, name, description;`
- 🐛 📋 Phase 4m — **`crafting_options.name` holds whole paragraphs** on ~9 rows (one is a 40-word sentence about unslotting Isle of Dread augments). The crafting scraper is putting prose into a name column. Repro: `SELECT id, length(name), name FROM crafting_options ORDER BY length(name) DESC LIMIT 10;`
- 🐛 📋 Phase 4m — **Set bonuses need the item router's three-way routing.** Surfaced when 4c renamed `[[True Seeing (enhancement)|True Seeing]]` to `True Seeing`, which made A1 fire: `set_bonuses` link only to `bonuses`, so a named *effect* conferred by a set has nowhere else to go and lands in the wrong table. Allowlisted in A1 with that reason recorded; the real fix is giving `insert_set_bonus_effects` the same bonus/effect routing the item path already has.
- ⚠ 📋 Phase 4m — **The committed `ddo.db` is not a build output.** One `build-db` run from it adds ~752 items from `.wiki-cache` (7,430 → 8,182) plus derived rows, and raises a new `items_have_equipment_slot` warning. The pipeline *is* idempotent (run 1 == run 2 across all 79 tables), but the committed state is the input, not the fixed point. 4c deliberately shipped the smaller, reviewed delta. Someone should decide whether to recommit a rebuilt database — and that decision is easier now that a rebuild is provably repeatable.
- ⚠ **Cache-derived *category* membership is not viable**, measured while building the offline enumeration: only 167 of 810 feat pages, **0** enhancement-tree pages, and 563 of 4,949 loot memberships are recoverable from `[[Category:]]` links in cached wikitext. Namespace enumeration from cache titles works fine (that is what shipped); any future plan depending on a category walk is blocked exactly as the API is.

### Stat identity (matters for the Phase 6 engine)

- ✅ **Shipped in 4c** (19 rows retargeted; stat 177 now holds 22 `Spell Save +N` rows and stat 21 retains 8 genuine `Spell Resistance +N`). **`{{Save|Spell|N}}` resolves to the wrong stat.** All 19 rows map to stat 21 (`Spell Resistance`) when stat 177 (`Spell Save`) exists and is correct. Every other save param resolves properly (`reflex`→19, `will`→20, `fort`→18, `curse`→122, `enchantment`→121, `illusion`→170) — only `spell` is wrong. Consequence: **spell saving-throw bonuses are recorded as Spell Resistance**, a completely different mechanic (saves run 1–8; SR runs 17–41). This is also why `Spell Resistance` is the worst of the dual-table cases below. Repro: `SELECT id, name, description, stat_id FROM bonuses WHERE description LIKE '{{Save|%pell%';`
- ⚠ **Standing constraint on validation design (no phase — this is a fact, not a task).** `bonuses.name` cannot be used as a validation oracle. A detector for "name disagrees with resolved stat" found **zero** hits, because `name` is *generated from* `stat_id` — so a wrong stat yields a wrong-but-self-consistent row. Validation must cross-check the **template source** against the stat. Recorded so no future check is built on the wrong signal.
- ✅ **Shipped in 4c** (`Spell Resistance` fixed; the 7 legitimate names allowlisted in A1 with a reason each). **An enchantment name in both `bonuses` and `effects`** — 11 names. Only one is a real bug (`Spell Resistance`, above); 7 are legitimately shared (`Concealment` — effects are named sources Blurry/Dusk/Lesser Displacement/Smoke Screen; `Wizardry` — AM/Archmagi/Magi tiers; `Fortification` — `heavy`; `Doublestrike` — `Calamitous Blows`; `Protection`; `Attack Bonus`; `Tendon Slice`) and get an allowlist with a per-entry reason; the rest (`Shatter` `+11`, `Temporary Spell Points` `0`) are the magnitude-in-modifier bug. Repro: `SELECT e.name FROM effects e WHERE EXISTS (SELECT 1 FROM bonuses b WHERE b.name=e.name OR b.name LIKE e.name||' +%') GROUP BY e.name;`
- 🐛 📋 Phase 4m — **`{{HELstats|...}}` multi-stat enchantments lose every stat but one, and resolve to none.** 6 rows where the description names 3–4 stats but the generated name keeps one and `stat_id` is NULL — e.g. id 4299 `name='Lightning Spell Power +30'`, `desc='{{HELstats|+25|L=+30}} Artifact bonus to Fire, Cold, Lightning, and Positive Spell Power'`. Repro: `SELECT id, name, description, stat_id FROM bonuses WHERE description LIKE '%HELstats%' AND stat_id IS NULL;`

### Name normalization

- ✅ **Shipped in 4c** (all 65 variant groups collapsed; `Clicky` is now one name with 206 rows). **Case/punctuation duplicate names, far beyond the known `Armor-Piercing` case.** `effects.name`: **19 variant groups affecting 462 rows** — `Clicky`/`clicky` (191+41), `Guard`/`guard`, `Bane`/`bane`, `Holy`/`holy`, `Flaming`/`flaming`, `Assassinate`/`assassinate`, `Cursed`/`cursed`, `Deathblock`/`deathblock`, `Entropic`/`entropic`, `Eversight`/`eversight`, `Power`/`power`, `Hp`/`hp`, `ArmorBonus`/`armorBonus`, `True Seeing`/`TrueSeeing`, `Blood Rage`/`Bloodrage`, `Efficient Metamagic`/`Efficient_Metamagic`, `Nearly Finished`/`Nearly finished`, `Armor-Piercing`/`ArmorPiercing`, and **`Random effect:`/`|* Random effect:`** (a leaked wiki table pipe). `bonuses.name`: 27 groups / 109 rows (`Wizardry`/`wizardry`, `Speed`/`speed`, `Doublestrike`/`doublestrike`). `enhancements.name`: 8 groups / 23 rows (`Self Reliant`/`Self-Reliant`, `Weapon Master`/`Weaponmaster`). `item_materials.name`: 8 groups / 16 rows. `items.name`: 3 groups / 6 rows. Repro: group by `lower(replace(replace(name,'-',''),' ',''))` and keep groups with >1 distinct name.
- ✅ **Shipped in 4c.** **Enum-ish columns inconsistent in case.** `item_weapon_stats.attack_mod` and `.damage_mod` both have `STR` *and* `Str`; `.damage_class` has `Bludgeoning`/`bludgeoning`; `items.race_required` has `Warforged`/`warforged` and `None`/`none`; `spells.spell_resistance` has `No`/`no`; `spells.range` has `Standard AOE`/`Standard AoE`; `class_bonus_feat_slots.slot_label` has `Bonus Feat`/`Bonus feat`. - ✅ **Shipped in 4c.** **Malformed `+-N` in 17 generated bonus names** — `Constitution +-2`, `Reflex Save +-2`, `Concentration +-50`.
